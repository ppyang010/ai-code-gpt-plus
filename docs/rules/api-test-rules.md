# API 测试规则

最后更新：2026-05-09

## 目的

本文件用于约束当前项目的接口联调测试文档如何编写、维护和更新，避免测试记录只停留在临时对话里，或因为格式不统一导致后续难以复用。

## 适用范围

- 当前项目的后端接口联调规则
- 当前项目的本地 `curl` 测试用例
- 当前项目的接口执行结果记录
- 当前项目的数据库辅助校验语句
- 当前项目的接口验证结论记录

## 核心规则

### 1. API 测试文档必须落盘

- 只要已经形成可重复执行的接口联调步骤，就应写入 `docs/backend/api-test-cases.md`
- 只要已经完成一次真实联调、回归或验证，就应写入 `docs/backend/api-test-results/`
- 不应只把接口测试命令留在聊天记录里
- 新增重要接口后，应尽快补对应测试用例

### 2. 测试文档要记录“真实可执行命令”

- 优先记录可以直接复制执行的 `curl` 命令
- 启动命令、请求头、路径参数、查询参数、请求体都要写完整
- 如果接口依赖本地 profile、数据库种子数据、环境变量，也要明确写出前提

### 3. 测试文档要记录“预期结果”和“联调检查点”

- 每个重要接口至少应包含：请求、预期、联调检查点
- 预期结果应优先描述响应结构、关键字段和成功条件
- 联调检查点应优先描述数据库变化、状态变化、SSE 事件顺序、日志或副作用

### 4. 测试状态必须真实

- `api-test-cases.md` 不记录某次执行的通过/失败状态
- 只有真正跑通过的结果，才写进对应的 `results` 文件
- 没有实际执行的，只能写“预期”或“待验证”，不能写成已完成结论
- 如果当前链路仍有 mock、回退逻辑或人工补数前提，必须明确写出来

### 5. 优先维护最小可用闭环

- 当前阶段优先维护能支撑本地联调的最小测试集
- 默认优先覆盖：服务可访问、会话创建、消息发送、消息查询、关键副作用落库
- 不需要一开始就把所有边界异常场景一次性补全

### 6. 涉及副作用的接口必须补数据库辅助检查

- 如果接口会写库、改状态、生成日志或额度记录，应补对应 SQL 检查语句
- 数据库校验应尽量直指关键表和关键字段，不写无关大查询
- 至少要能回答“这次请求到底有没有真正落库”

### 7. SSE 或流式接口必须写清事件顺序

- 对流式接口，要明确事件类型和顺序，例如：`message_start`、`message_delta`、`message_end`
- 如果已经从 mock 切换为真实流式，也要在文档中显式更新
- 若存在 token、finish_reason、调用日志等尾部信息，应写在检查点里

### 8. 文档更新要跟代码状态同步

- 接口行为变化后，要同步更新 `docs/backend/api-test-cases.md`
- 新增一次实际联调后，要同步补 `docs/backend/api-test-results/` 中的结果记录
- 如果规则层面的约束变化，要同步更新本规则文件或 `project-rules.md`
- 不应出现代码已变更但测试文档仍描述旧行为的情况

### 9. `cases` 和 `results` 必须分层维护

- `docs/backend/api-test-cases.md` 只保留稳定的标准测试步骤
- `docs/backend/api-test-results/` 只保留某次实际执行结果
- 不应把“当前测试结论”“已验证通过”“本次返回内容”继续写回 `cases`
- `task.md` 只保留项目级测试结论，不承担详细接口执行历史

## 推荐结构

新增一个接口测试项时，建议按下面结构维护：

````md
### N. 接口名称

#### 请求

```bash
curl ...
```

#### 预期

- 返回什么
- 关键字段是什么

#### 联调检查点

- 数据库变化
- 事件顺序
- 关键副作用
````

新增一个执行结果文件时，建议按下面结构维护：

````md
# 2026-05-09 local 联调结果

## 执行信息

- 执行日期：
- 执行环境：
- 执行主题：
- 对应用例：

## 结果摘要

- 通过 / 失败 / 阻塞
- 实际返回摘要
- 关键数据库校验

## 详细记录

### 用例 N

- 请求结果：
- 副作用结果：
- 问题与后续动作：
````

## 当前项目的默认要求

- 默认后端项目目录是 `gpt-plus-core`
- 默认使用 `jenv exec` 执行启动和编译命令
- 默认服务地址是 `http://127.0.0.1:8080`
- 当前临时身份通过 `X-User-Id` 传入
- 对真实模型链路测试，要明确说明模型配置和密钥前提
- `results` 文件命名规则为：`YYYY-MM-DD-环境[-主题].md`
- 环境必须进文件名，主题可以为空
- 同一天同环境多次执行时，应补主题避免文件重名
